# 已知限制

單一無線電、單一藍牙連線帶來的幾個限制，大多改不掉，知道就好。

## WiFi 與藍牙共用天線（C3／S3）

ESP32 只有一組無線電，藍牙和 WiFi 分時共用。送圖的那 30–60 秒韌體會把無線電拉到全速
以免傳輸被餓死，這段期間網頁後台會變頓——正常現象。平常閒置時無線電會進省電模式，
所以只有傳圖當下會這樣。

## 熱點與家用網路必須同頻道

同樣因為只有一組無線電：SoftAP 熱點和連上的家用網路**必須待在同一個頻道**（所有型號
都一樣，換 S3 也不會變）。所以 ESP32 連上路由器的瞬間，熱點會被迫換到路由器的頻道，
正連著熱點的裝置會斷線幾秒再自動連回。**熱點本身不會關**，`192.168.4.1` 一直有效。

掃描 WiFi 也會短暫佔用無線電，所以後台不會自動輪詢掃描，要按按鈕才掃。

## 日曆一次只能被一台裝置連著

這是日曆本身的限制。連著 ESP32 時官方 App 連不上，反之亦然。若日曆還記著舊配對，會
搜尋得到、一連線就在配對階段被日曆切斷（`connect: ESP_FAIL`）——要先在日曆上回復出廠
預設值，見 [getting-started.md](getting-started.md)。

## 送圖偶爾以 `0201` 收場

日曆偶爾會在收完整份 payload 前回報資料不完整（`0201`）。韌體會自動重試（最多三次），
實測多能在重試後成功；連續失敗才會在後台顯示錯誤。

## 電量顯示可能偏低

後台的電量百分比疑似把 metadata 解析錯了，有時會顯示得比實際低（實測充飽也只到 5）。
不影響運作，尚未細追。旁邊的原始回覆值（`0x....`）保留著，方便日後對照。

同一個數字現在也會跟著 Tesserae 的 heartbeat 送出去（`battery_pct`），所以 Tesserae
的電量卡片、電量歷史圖和 Home Assistant 的 battery sensor 會一起偏低。刻度的來龍去脈
和「要改就三個地方一起改」的清單在 [protocol.md](protocol.md#電量的編碼尚未確認)。
